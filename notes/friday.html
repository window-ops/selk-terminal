Chapter 1: The counter#

For more than a year, since he settled in Scotland, Cornelius has come to the same restaurant on the upper floor of a shopping mall in Glasgow once every two weeks, usually in the quiet hour after lunch, and he orders at the counter like any other regular. Last week the news about the Selk site on Titan was published, with a photograph of its only supervisor printed beside the article. Kaylen read it on her phone during a break and recognised the face of the man who comes in every second Friday. Her shift ended at four today, and she has stayed behind the counter past it, waiting for him to come in.

Kaylen is in her twenties, with pale skin, light freckles across her nose and cheeks, dark brown eyes and thick dark brows. Her long, wavy hair is red throughout, with a set of purple strands falling on her right side and a set of pink strands on her left. Her skin is unmarked and unpierced, and her lips have a muted red tint. She wears a black shirt, her apron already folded on the shelf behind her, and she stands at the end of the counter with a clear view of the escalator.

from dataclasses import dataclass

@dataclass(frozen=True)
class Rule:
    kind: str      # "max" or "min"
    limit: float
    zone: str      # site zone the rule protects

class SafetyRules:
    def __init__(self, rules):
        # rules: {rule_id: Rule}
        self.rules = rules

    def weaker_than(self, installed):
        for rule_id, old in installed.rules.items():
            new = self.rules.get(rule_id)
            if new is None:
                return True        # rule removed
            if new.kind == "max" and new.limit > old.limit:
                return True        # ceiling raised
            if new.kind == "min" and new.limit < old.limit:
                return True        # floor lowered
        return False

    def merge(self, other):
        combined = dict(self.rules)
        combined.update(other.rules)
        return SafetyRules(combined)

portcheck reads the executable of a program and reports what would stop it from running on a different processor: byte order, word size, unaligned reads from packed data, instructions that only exist on one processor, and hand-written assembly.

Most programs in the world are portable. This tool is for finding the ones that are not before you spend 14 months on them.

Limits
  • portcheck only checks whether the processor can run the program. It does not check memory, storage or any other hardware.
  • It reads executables, so results can include false positives and false negatives. Treat a PASS as "worth trying" and a FAIL as "look here first".
  • It works best on programs written in C and assembly.
  • It cannot judge programs that run through an interpreter, such as Python or ECMAScript. Those report UNKNOWN, since the answer depends on the interpreter.

Intel Virtual Parallelism Technology (Intel VPT) Developer Guide

ID
784210
Version
Revision 7
Classification
Public

Applies to Intel Core processors with integrated graphics and no discrete graphics card

Overview

Intel VPT lets a processor without a discrete graphics card run parallel workloads, such as neural network inference and data validation, as if a separate compute device were installed. The processor presents a virtual compute device to the operating system and to applications. Work sent to this device is spread across the vector units of the processor cores.

How it works
  1. At start-up, the firmware reduces the memory allocated to integrated graphics to the minimum needed for the display in use.
  2. The memory released, together with a reserved region of system RAM, forms the parallel value store. Values that a workload reads often, such as network weights and lookup tables, are kept there so that the cores do not fetch them again for each pass.
  3. The scheduler assigns parallel work to vector units that are idle and returns them to general work when the load rises.
  4. The virtual device is listed to software through the OpenCL and Level Zero interfaces as "Intel VPT Virtual Compute Device".
Performance

A virtual compute device is slower than a discrete graphics card with the same number of parallel lanes. Throughput depends on memory bandwidth and on the share of cores that are idle. Display output has priority, and parallel work slows down while the integrated graphics are under heavy load.

Memory reported to applications

The device reports the size of the parallel value store as its device memory, between 2 GB and 16 GB depending on the firmware setting. This memory belongs to system RAM. Applications that allocate the full reported amount reduce the memory available to every other program.

Known issues
  • Older applications that list compute devices may treat the virtual device as a discrete graphics card and send it workloads sized for one.
  • Applications that benchmark compute devices on first launch may stop responding while the benchmark runs on the virtual device.
  • Older builds of ImageMagick with OpenCL acceleration turned on have been reported to crash when they select the virtual device and allocate its full reported memory.
Workarounds
  • Update the application to a version that recognises virtual compute devices.
  • Turn off OpenCL in the application. For ImageMagick, set the environment variable MAGICK_OCL_DEVICE=OFF.
  • Exclude the application from Intel VPT in the operating system's per-application compute settings.

Tool use evaluation and middle workflow detection: protection or a moral standard?

M. Novák, CESEA Public Models Team, Brno
A. Ionescu, CESEA Legal Office, Bucharest
K. Wiśniewska, CESEA Human Factors Group, Kraków

Summary GenPlan proposes two measures for the current, previous and next public releases of the NTorch LLM. Their stated purpose is to stop the public model from being used to produce material that floods social media platforms. This critique accepts the purpose and questions who defines the material, how the measures work, and whether they reach the people they are aimed at.
The proposals
Tool use evaluation
Evaluates how a user writes prompts and calls tools during a session: the number of near-identical requests, the use of templates, the speed of submission and the tools chained after each answer.
Middle workflow detection
Estimates whether a prompt or an uploaded document comes from another tool that forms part of a clickbait pipeline. This includes text dropped in from other AI models. The detector was trained in part on material from 23 paid courses that teach the mass production of AI-generated content for social media, which CESEA reviewed in 2096.
Effect
A session judged to be part of such a pipeline is slowed, then refused. The refusal can be reported as false.
Where the definitions come from

The definitions of harmful material in both measures are detailed and well written. They are based on how Eastern European states experienced information warfare:

YearEvent
2007Estonia: coordinated cyberattacks on government, bank and media sites during a dispute over a Soviet war memorial
2022Czechia: the national domain registry blocked several disinformation websites after the Russian invasion of Ukraine
2023Slovakia: a fabricated audio recording of an opposition leader spread online two days before the parliamentary election
2024Romania: the Constitutional Court annulled the first round of the presidential election after reports of a coordinated campaign on social media
Critiques
  1. Whose standard: The definitions reflect one region's experience. A public model used across the Federation and outside it applies that experience to every user. Satire, activist campaigns and small publishers who automate honest work can be caught by the same rules.
  2. Watching how people work: Tool use evaluation records behaviour as well as content. The proposal does not say how long these records are kept or who may read them.
  3. Displacement: The weights of NTorch are public. A determined operator can clone them and run the model on their own servers, where neither measure applies. The measures then burden ordinary users most and organised operators least.
  4. The role of CESEA: CESEA is a space agency. It is neither Anthropic nor OpenAI, though its models are closer in capability to those of Anthropic. The NTorch LLM is a public interface built to show what NTorch, a model based on PyTorch, can do. CESEA is required by law to publish the model and has no legal duty to run a public service for it. Critics ask whether a showcase should set content rules for the public. Supporters answer that a public institution cannot let its showcase become a tool for flooding platforms, and that the showcase is good publicity for CESEA only while it is trusted.
Recommendations
  1. Publish the criteria of both detectors and the list of reviewed courses.
  2. Keep the record of tool use for no longer than 30 days, readable only by the safety office.
  3. Have the definitions reviewed by members from at least three regions of the Federation.
  4. Measure, after one year, how much flooding moved to cloned copies, and withdraw the measures if the public model was not a significant source.

Abstract

This paper describes how the panel robot presented by the research center in Brno in 2049 was adapted to renovate concrete element housing estates in Helsinki. The Brno robot was built for new construction: it runs on rails along a building, lifts wall and floor panels from a stack, sets them in place and welds their joints. Helsinki needed a different type of robot. Its estates of the 1960s and 1970s were built from standardized elements, and their sandwich facade panels now have cracked outer shells, corroded ties and too little insulation. The work has to be done while residents stay in their homes. Three Finnish additions made this possible: short rail sections that can be laid between the trees and parking spaces of forest suburbs, a removal head with a disc saw and a heated wire that takes off cracked outer shells and old insulation, and a camera that scores cracks, trained on images of 2 400 facades in Helsinki. In a pilot in Kontula in 2050 and 2051, the time needed to renovate one stairwell fell from 14 weeks to 5. The paper argues that the final shape of the robot, a narrow carriage on short rails with interchangeable heads, follows from the form of the suburbs it had to work in.

1 Introduction

A large share of Helsinki's housing stands in suburbs built between the early 1960s and the late 1970s, when migration from the countryside to the cities was at its height. Most of these buildings were assembled from precast concrete elements. From the late 1960s the BES system standardized the elements and the joints between them, so that buildings could be designed and put up quickly by different contractors from the same parts.

The same standardization makes these buildings suitable for robots. A robot that recognizes one type of panel and one type of joint can work on hundreds of buildings. The robot presented in Brno in 2049 relied on this for new construction, and its team built a ten-story block on the Lesná estate in eleven weeks with three robots and one supervisor.

Renovation poses other problems. The site is narrow, the building is occupied, and the parts to be removed are damaged in ways that differ from one panel to the next. Abstract

Chemosynthetic organisms living in liquid methane could draw energy from the reaction of acetylene with hydrogen, C2H2 + 3 H2 → 2 CH4, and would leave two signs in their surroundings: hydrogen below its background level and acetylene below detection. The laboratory at Selk crater, completed in 2079, tested for both in plots of regolith soaked with liquid methane. Between 2083 and 2097, the two active plots, 3 and 6, showed hydrogen at 1 m between 6 % and 11 % below the background of 0.10 %, with acetylene below detection, while the control plot showed neither. Abiotic explanations were examined: catalysis on regolith minerals, drift in the gas sensors, and the consumption of hydrogen by the export plant EX-1 after 2092. None accounts for the pattern across plots and years. A third active plot, plot 9, was lost under a structural footing in 2092. We conclude that chemosynthetic life in the regolith of Selk crater is highly likely, and we set out the measurements that would confirm it.

At Selk the removal head was used both to cut cores and to remove cracked parts for repair, and the images of 2 400 Helsinki facades on which the crack camera was first trained became the starting data of the site's crack finder.

COMMENT 02 October 2097

Selk's microbes need a second laboratory

The evidence for life on Titan is the most open data set in the history of astrobiology, and still nearly impossible to reproduce. Here is what it would take.

By Laura Bennett & Kenji Mori

PDF version

Last month, CESEA and 1,048 authors reported in Frontiers in Astronomy and Space Sciences that the regolith at Selk crater on Titan is highly likely to contain chemosynthetic life. The claim rests on hydrogen below its background level and acetylene below detection in two active plots, measured over fourteen years. It deserves to be taken seriously but it also deserves to be tested by someone else.

Open is not the same as reproducible

No space agency has published more than CESEA. Every finding, every line of source code, every drawing of every component is public. Yet openness does not let anyone repeat the experiment. All of the measurements come from one site, one laboratory, and one set of gas sensors installed in 2079. To reproduce the result, another team would need another laboratory on Titan.

⋯
Machines that find and maintain

At NASA and ESA, scientists design the experiment and the instruments return readings. At Selk, the site units chose where to sample, flagged the zones where life might be, and maintained the site around those zones. The same gate that detected the signs of life also stopped the units from cutting, heating or drilling there. Discovery and maintenance are tied together in one system, which makes it hard to separate what was found from what the system was built to look for.

The unauthorized update

The original paper is clear about the worst problem. From 19 May 2092 to 6 January 2097, the gate was switched off by an update signed with a valid key and sent from a remote account. During that time a footing was poured over plot 9, and the export plant EX-1 consumed local hydrogen. Any sample from those years was taken by units running a package that no crew had reviewed. These data need to be treated separately, and the authors' own correction for EX-1 should be checked by a team that did not write it.

⋯
A thousand authors

The paper lists 1,048 authors for a discovery made largely by machines. Most of them are contributors: engineers, programmers, designers of the units, laboratory staff and the site supervisor. Their work made the result possible, and the contributions section records it fairly. But an author list of this size makes it hard to know who is responsible for each claim. Journals, including this one, should ask CESEA to separate the researchers who stand behind the conclusion from the much larger group who built the means to reach it.

What would settle it

A second laboratory at another site on Titan, built and run by a different team, with a crew of at least three. Until then, the microbes of Selk remain highly likely, and unconfirmed.
